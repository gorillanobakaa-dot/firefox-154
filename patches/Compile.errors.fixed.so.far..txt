Cause:   The Gorilla patch had commented out the GPU process ForceDisable block for
         Wayland in gfxPlatformGtk::InitPlatformGPUProcessPrefs(), with the comment
         "GORILLA: Allow GPU process on Wayland — VA-API decode needs it".

         This enabled the GPU process on Wayland, but the GPU process compositor widget
         (GtkCompositorWidget) receives a GtkCompositorWidgetInitData struct that contains
         ONLY X11 fields: XWindow (uintptr_t), XDisplayString (nsCString), IsX11Display (bool).
         There are NO Wayland surface fields in this struct.

         So in the GPU process:
           GtkCompositorWidget::GetEGLNativeWindow()
             → mWidget is nullptr (no nsWindow in GPU proc)
             → returns nullptr
           GLContextProviderEGL.cpp:334
             → window = GET_NATIVE_WINDOW_FROM_COMPOSITOR_WIDGET(aWidget)
             → window = nullptr
             → "window is null" error, returns EGL_NO_SURFACE
           RenderCompositorEGL tries EGL → fails
           Falls back to SW-WR (RenderCompositorSWGL)
             → StartRemoteDrawingInRegion → mWidget is null → returns nullptr DT
             → "RenderCompositorSWGL failed mapping default framebuffer, no dt"
           Both paths fail → black window.

         The previous "fix" of GDK_BACKEND=x11 worked by routing Firefox through
         XWayland (X11 protocol over Wayland), which bypasses the EGL/Wayland codepath
         entirely but gives up native Wayland compositing.

         The VA-API concern was misplaced: VA-API decode does NOT require the GPU process.
         It runs in the RDD (Remote Data Decoder) process, controlled by:
           media.rdd-ffmpeg.vaapi.enabled = true
           media.rdd-process.enabled = true

           gfx/thebes/gfxPlatformGtk.cpp lines 326-335

             #ifdef MOZ_WAYLAND
               if (IsWaylandDisplay()) {
                 FeatureState& gpuProc = gfxConfig::GetFeature(Feature::GPU_PROCESS);
                 gpuProc.ForceDisable(FeatureStatus::Blocked,
                                      "Wayland does not work in the GPU process",
                                      "FEATURE_FAILURE_WAYLAND"_ns);
               }
             #endif
             }

           obj-x86_64-pc-linux-gnu/tmp/profile-default/user.js
