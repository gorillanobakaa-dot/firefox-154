- **HK-1 — "FastTanh soft-knee limiter" wording at AudioDestinationNode overstates the code.**
  §12.1 / §12.3 / the DEVELOPER + AUDIT tracks describe `AudioDestinationNode.cpp` as adding a
  "second **FastTanh** soft-knee limiter" at 0.9. Ground truth (`AudioDestinationNode.cpp:214-238`):
  it is a real, pref-gated soft-clipper, but (a) it does **not** call the `FastTanh` function
  (`grep FastTanh` = 0 hits in that file — `FastTanh` lives only in AudioStream.cpp), it inlines
  a different Padé tanh approximation `x*(27+x²)/(27+9x²)`; and (b) it hard-clamps at ±1.0 across
  the full range rather than using a 0.9 soft knee. The feature EXISTS and is functionally a
  tanh-shaped soft-clip; only the "FastTanh"/"soft-knee @0.9" naming is imprecise. Detected by:
  grep for `FastTanh` in the file returning zero.
- **HK-2 — §12.3 table cell "zero `std::max`" is a whole-file overstatement.** The file has 2
  `std::max` (`FFmpegVideoDecoder.cpp:1350` decode-thread floor, `:2236` Vulkan queue index) —

  growth) holds. The literal phrase "zero std::max" read against the whole file is false.

  reintroduce the blocklist-loses bug. (§12 supersedes the body, but the body was never corrected.)
