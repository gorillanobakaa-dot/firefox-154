## Tango neutralised (1)

**`toolkit/themes/shared/icons/warning.svg` — false "applied" claim in the master log.**
The master log (SECTION C: "findbar.css + warning.svg style the chrome://global/skin widgets";
DEVELOPER Kill Switches: "toolkit/themes/shared/findbar.css (+ warning.svg) … Styles the toolkit-side
widgets … master-redirect.css cannot reach") asserts warning.svg is an applied styling change.
**Ground truth: the live warning.svg is byte-identical to the vanilla vault** (`cmp` → identical,
1223 B stock Mozilla warning triangle). The `.patch`, if applied, would replace it with a
**1,540,440-byte single-line custom SVG** — it was never applied to the tree (or was reverted).
- **Falsifiable check that caught it:** `cmp VANILLA/…/warning.svg LIVE/…/warning.svg` → identical;
  applying the patch to vanilla yields a 1.5 MB file, live is 1223 B.
- **Note on which side is wrong:** the *tree* is arguably the correct state — a 1.5 MB warning icon
  contradicts the low-memory target. It is the **doc that overclaims**, not the tree that is broken.
  findbar.css (the other half of the same claim) **does** pass byte-exact, so the global-skin styling
  is only half-present.
- **Owed (not done here — audit is read-only):** correct the master log so warning.svg is recorded as
  *stock/unapplied*, and either drop the stale 1.5 MB `.patch` or re-scope it. **Do NOT apply the
  warning.svg patch to the tree.**
